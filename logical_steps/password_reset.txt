1. a user forgot his password so he make a POST request to : api/users/auth/reset/password with the email in the request body
2. in the api/users/auth/reset/password route we check if the email is in our DB then we generate a resetPasswordToken and assign it to the user with that email then send an email to that email
3. the email contain a link with a GET request to api/users/auth/reset/password/:userId/:resetPasswordToken in that route we do tow tasks:
4. the first one is checking the email and check if that email in our DB and has a resetPasswordToken and that token in the DB equals the incoming token
5. the second one is that that route renders a web page that has a form with two inputs first is the password second is the confirm password and at last a submit 
6. the form make a POST request to : api/users/auth/reset/password/confirm with a body containing the new password and the confirm password and the userId
7. the api/users/auth/reset/password/confirm  route will get the user with the userId then check if the password and the confirm password are equaled then we remove the resetPasswordToken then hash the new password and assign it to the user then return a message: "password was reseted successfully."
