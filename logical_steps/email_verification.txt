**Senario 1.the user registers for the first time**

1. user register with an email and password to our endpoint: api/auth/register
2. check the email already exists in our DB or not. if it exists, throw BadRequestExeption("invalid email or password"), if not go on
3. hash the password
4. make a new user with the email & hashed password
5. generate a verificationToken then assign it to the new user
6. save the new user to the DB
7. send a verification email to the email to verify if the new user own that email or not
8. respond with a succes message: "Registered successfully. A verification email will be sent to you"
9. if the new user really own the email he will get an email with a verification link to click
10. the verification link to click makes a GET request to our server to the endpoint: api/auth/users/verify/email/:userId/:verificationToken
11. our server recives the request then gets the :userId & :verificationToken
12. we get the user with the :userId. if the id is invaild we throw NotFoundExeption("user not found") else we go on
13. we check if the user.verificationToken === null in the DB and if the user.verificationToken === verificationToken if all good we go on
14. after checking that the user has a verificationToken in the DB and it's the same one as the incoming verificationToken
    we override it to be null in the DB then change the is_email_verified in the DB to be true then the user can login and consume our api
